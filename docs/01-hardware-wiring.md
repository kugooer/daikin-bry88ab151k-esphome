# 硬件与接线

## 1. ZE08C 引脚定义（关键）

厂商规格书给出的端口顺序，与市面上常见的「VCC-GND-TX-RX」模块**完全相反**：

| 端口 | 定义 | 说明 |
|---|---|---|
| 1 | 电源 **负（−）** | GND |
| 2 | 电源 **正（+）** | 5 V DC |
| 3 | A（RX） | 模块接收，主动上传模式下可不接 |
| 4 | B（TX） | 模块发送，数据从这里出来 |

> ⚠️ **没有防反接保护**。把 5 V 接到端口 1、GND 接到端口 2，模块当场损坏，且不会有任何提示。

引脚顺序 `1=负 2=正` 与常见模块相反，是本次排查中耗时最久的一个坑。

## 2. 与 ESP32 的连接

| ZE08C | 中间环节 | ESP32 |
|---|---|---|
| 端口 1（−） | 直连 | GND |
| 端口 2（+） | USB 母头 5 V | 不接 ESP32 的 5V，避免与 USB 供电冲突 |
| 端口 3（A/RX） | — | 可悬空 |
| 端口 4（B/TX） | **1 kΩ + 2 kΩ 分压** | GPIO5 |

### 为什么必须分压

ZE08C 的 UART 是 **5 V 电平**，ESP32 的 GPIO 是 3.3 V 且不耐 5 V。

```
ZE08C 端口4 ──[1kΩ]──┬── GPIO5
                     │
                  [2kΩ]
                     │
                    GND
```

分压比 `2 / (1 + 2) = 0.667`，5 V → **3.33 V**，安全落在 ESP32 的输入范围。

**分压接反的典型症状**：GPIO5 恒为低电平、日志显示 `GPIO5 电平=0` 且零字节。因为下臂接地会把信号直接拉到 GND。

### 必须共地

模块 5 V 由 USB 母头单独供给时，**USB 母头的 GND 必须与 ESP32 的 GND 连通**。不共地时 UART 没有参考电平，表现同样是「零字节 + 电平异常」。

## 3. 供电实测方法

用万用表**并联**测量（不断开任何线）：

| 表笔 | 触点 |
|---|---|
| 黑笔 → `COM` | 模块端口 1（−） |
| 红笔 → `VΩ` | 模块端口 2（+） |
| 档位 | `V⎓`（直流电压，V 带直线加短横） |

**必须在设备通电、模块插着的状态下测**，断电测到 0 V 是正常的。

| 读数 | 结论 |
|---|---|
| 4.75 – 5.25 V | 供电正常，问题在 TX 那一路 |
| ≈ 3.3 V | 误接到 ESP32 的 3V3，ZE08C 需要 5 V |
| 0.0 V | 未供电：查 USB 母头 5 V、线序、焊点 |
| 负值 | 极性反了（红黑笔对调可确认） |

模块工作电流约 10 mA。若接上模块后电压掉到 4 V 以下，说明线路压降过大（线太细或接触电阻高），会导致模块反复重启而无输出。

## 5. 上机前自查清单

1. 端口 1–2 之间电压 = 5.0 V
2. 端口 1 与 ESP32 GND 之间电阻 ≈ 0 Ω（蜂鸣档响）
3. 端口 4 经分压后接到 GPIO5，分压中点对地约 2 V（模块发送时）
4. 上电后 GPIO5 空闲态应为**高电平**（UART 空闲态 + 内部上拉）
5. `1k/2k` 分压不得接反：**1 kΩ 串在模块 TX 与 GPIO5 之间，2 kΩ 接在 GPIO5 与 GND 之间**

```bash
# 不经过 ESP32，直接验证模块是否在输出
python3 tools/capture_ze08c.py 25 /dev/cu.usbserial-11440
```

接线：`TTL GND → 端口1`、`TTL RX → 端口4`，模块 5 V 外供且共地，**TTL 的 VCC 不要接**（5 V 灌进 3.3 V 的 TTL 会烧芯片）。
