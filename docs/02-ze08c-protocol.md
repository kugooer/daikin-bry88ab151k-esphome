# ZE08C 协议分析

本文记录 **ZE08C（TP-501）** 的实际串口协议，以及它与 **ZE08-CH2O** 的差异。所有帧数据来自真实设备抓包，而非仅照抄规格书。

## 1. 与 ZE08-CH2O 的根本差异

| 项目 | ZE08-CH2O（上游驱动支持） | **ZE08C（本项目实测）** |
|---|---|---|
| 工作模式 | 查询-应答（主机发 `FF 01 86 ...`） | **主动上传**，约 1 帧/秒 |
| 帧长 | 9 字节 | **6 字节** |
| 帧头 | `0xFF` | **`0x2C`** |
| 校验算法 | 二补数：`~(B2+…+B8)+1` | **累加取低字节：`(B1+…+B5) & 0xFF`** |
| 浓度字段 | 多个（含两路重复值） | `B2B3`，单位 µg/m³ |
| 主机需发命令 | 是 | **否** |

这解释了一个典型症状：把 ZE08C 接到为 ZE08-CH2O 写的驱动上，驱动发送查询命令后等待 9 字节应答，而模块只是自顾自地每秒推 6 字节——日志表现为「30 秒只收到 1 个字节」或「大量字节但帧全非法」。

## 2. 帧结构

```
字节序号   B1    B2   B3    B4   B5    B6
含义      0x2C  浓度H 浓度L 量程H 量程L  校验和
```

| 字段 | 含义 |
|---|---|
| `B1` | 模块固定地址 `0x2C` |
| `B2 B3` | 甲醛浓度 = `B2 × 256 + B3`，单位 **µg/m³** |
| `B4 B5` | 模块自报满量程（见第 4 节，**不同批次不同**） |
| `B6` | 校验和 = `(B1+B2+B3+B4+B5) & 0xFF` |

浓度换算：`mg/m³ = (B2×256+B3) / 1000`。因为数值恰好相等，驱动直接以整数 µg/m³ 上报，不做浮点。

## 3. 逐帧验算

### 3.1 规格书给出的示例

```
帧：2C  00  57  03  E8 ┃ 6E

校验和 = 0x2C + 0x00 + 0x57 + 0x03 + 0xE8
       = 44 + 0 + 87 + 3 + 232 = 366 = 0x16E
       → 取低字节 0x6E                    ✓ 与 B6 一致

甲醛 = 0×256 + 0x57 = 87 µg/m³ = 0.087 mg/m³
```

### 3.2 本机实测帧（v4 固件日志）

```
帧：2C  00  0E  07  D0 ┃ 11
校验和 = 44 + 0 + 14 + 7 + 208 = 273 = 0x111 → 0x11   ✓
甲醛 = 14 µg/m³ = 0.014 mg/m³

帧：2C  00  05  07  D0 ┃ 08
校验和 = 44 + 0 + 5 + 7 + 208 = 264 = 0x108 → 0x08    ✓
甲醛 = 5 µg/m³

帧：2C  00  22  07  D0 ┃ 25
校验和 = 44 + 34 + 7 + 208 = 293 = 0x125 → 0x25       ✓
甲醛 = 34 µg/m³
```

校验和三帧全中，且浓度随时间在 5→34 之间自然变化，说明协议的解读是正确的，模块也在实时采样而非输出固定值。

## 4. 满量程字段：规格书与实际模块不符

这是本项目耗时最长的坑。

| 来源 | `B4 B5` | 换算 |
|---|---|---|
| 规格书示例 | `03 E8` | 1000 µg/m³ |
| **本机实测模块** | **`07 D0`** | **2000 µg/m³** |

初版驱动把这个字段当固定值做合法性校验（`buf[3]==0x03 && buf[4]==0xE8`），结果每一帧正常数据都被判为「满量程字段异常」，随后调用 `drop_(1)` 滑动重同步，导致缓冲区错位、下一帧继续判错，形成连锁：

```
[W][ze08c]: 累计 366 字节 / 有效帧 0 / 异常帧 361
[D][ze08c]: 满量程字段异常: 07 D0（本帧 2C 00 0D 07 D0 10）
```

**修正**：合法性判定只保留两条最可靠的依据——**帧头 `0x2C` + 校验和**。量程字段仅在首次收到时打一条 INFO：

```
[I][ze08c]: 模块标称满量程 2000 µg/m³ (0x07D0)
```

修正后 150 帧连续通过、异常帧 0。附带好处：同一份固件对 1000 与 2000 µg/m³ 两种版本模块都适用。

## 5. 驱动实现要点（`esphome/ze08c.h`）

| 机制 | 说明 |
|---|---|
| 滑动窗口组帧 | 缓冲区为空时必须是 `0x2C` 才入队，否则丢弃；满 6 字节即解析 |
| 帧头复核 | `parse_()` 里再查一次 `buf_[0]==0x2C`。滑动重同步后首位未必仍是帧头，仅凭校验和有极小概率凑出伪帧 |
| 校验失败重同步 | `drop_(1)` 后继续找下一个 `0x2C`，不整段丢弃 |
| 上报节流 | 模块 1 帧/秒，数值变化立即上报，否则 10 秒心跳；避免刷爆 API |
| 日志限速 | 读数日志最多 10 秒一行，累计统计 60 秒一行，与 CM1106 节奏对齐 |
| 引脚电平诊断 | 构造参数传入 RX 引脚号，每 60 秒 `digitalRead` 一次：恒 0 → 被外部拉低；恒 1 → 线路空闲（模块没发） |
| 原始报文抓取 | `#define ZE08C_RAW_LOG` 打开后按 24 字节一段打印 hex，排障用，默认关闭 |

## 6. 独立验证工具

不经过 ESP32，直接抓模块原始字节，可一次区分「模块没输出」和「协议/波特率不匹配」：

```bash
python3 tools/capture_ze08c.py 25 /dev/cu.usbserial-11440
```

脚本会打印原始 hex、帧解析结果、上传周期，并给出三种结论之一：

- `模块完全没有输出` → 供电/极性/TX 接错/未共地
- `确认为 ZE08C 协议` → 模块正常，问题在 ESP32 侧
- `有数据但无法解析为 ZE08C 帧` → 可能是 ZE08-CH2O（9 字节 `0xFF` 帧）或波特率不符

## 7. 尚存的不确定性

协议层面 `B2B3` 就是 µg/m³ 原值，这一点由校验和与帧结构一致性支撑。但**未能排除** 2000 量程版本在模块内部对数值做了缩放的假设——要判定绝对精度，需要在已知浓度环境下与标准甲醛检测仪比对。当前洁净空气下读数 5–11 µg/m³，位于合理区间，据此倾向前者。
