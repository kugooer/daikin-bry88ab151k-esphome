# 排查实录：CH2O 从 NA 到出数

按时间顺序记录整个过程，包括**走错的弯路**。现象 → 判读 → 动作，可以直接当参照表用。

## 阶段 0：基线

刷入上游 `daikin-bry88ab151k-ch2o-2105.bin` 后：

| 通道 | 状态 |
|---|---|
| CO₂ / PM2.5 / TVOC / 温湿度 | 正常 |
| **CH2O** | **NA（无数据）** |

其余通道正常，说明主控、供电、I²C 总线都没问题，问题锁定在甲醛这一路。

## 阶段 1：两个错误的怀疑方向

### 弯路 A：以为驱动没编进去

日志里完全看不到 `ze08` 相关输出，于是怀疑驱动未被编译。实际情况是：

```c
#ifdef ZE08_DEBUG
  ESP_LOGD(TAGZE08, "...");
#endif
```

而 `ZE08_DEBUG` 宏在文件里被注释掉了。**预处理器会把这些日志字符串整个剔除**，`strings firmware.bin` 自然搜不到。取消注释后日志立刻出现——驱动一直都在。

> 教训：镜像里搜不到字符串，不等于驱动没编入，先看 `#ifdef`。

### 弯路 B：以为是应答时序

原驱动在 `write_array()` 发出查询命令后**立即** `available()` 判断有无数据。9600 波特率下模块来不及应答，于是静默 `return`。确实是个缺陷，但改完仍然 NA——因为这根本不是 ZE08-CH2O。

## 阶段 2：确认型号是 ZE08C

拿到厂商规格书后才明确：硬件位置虽是「ZE08-CH2O 的位置」，实际装的是 **ZE08C（TP-501）**，协议完全不同：

| | ZE08-CH2O | ZE08C |
|---|---|---|
| 模式 | 查询-应答 | 主动上传 |
| 帧长 | 9 字节 | 6 字节 |
| 帧头 | `0xFF` | `0x2C` |
| 校验 | 二补数 | 累加取低字节 |

也就是说，原先的驱动在等一个永远不会到来的应答。重写为 `ze08c.h` 后，仍然 NA。

## 阶段 3：决定性证据来自引脚电平

新驱动加了诊断：每 30 秒打印累计字节数 + `digitalRead(RX)`。

```
[W][ze08c]: 30秒内未收到任何字节｜GPIO5 电平=0｜检查：模块5V供电、端口1接GND、端口4(TX)接GPIO5、是否共地
```

**`电平=0` 是异常值**：UART 空闲态必须是高电平，而且 GPIO5 本身是带内部上拉的 strapping 引脚，即使悬空也应读到 1。恒定读到 0，只能是**被外部硬拉到地**。

顺带一个中间态证据：接线松动的瞬间只收到 **1 个字节**。这排除了「波特率不对」（那样会看到大量整齐的垃圾字节）和「协议不匹配」（那样字节数会与帧速率对得上）。

结论：TX 那根线接到了 **端口 1（GND）**。本模块端口顺序是 `1=负 2=正 3=RX 4=TX`，接第一脚就是接地——完美符合「电平 0 + 零字节」。

修正接线后：

```
[D][ze08c]: RX 6 字节: 2C 00 0E 07 D0 11
[I][ze08c]: 累计 186 字节 / 有效帧 0 / 异常帧 181｜GPIO5 电平=1
```

数据来了，但**每一帧都被判为非法**。

## 阶段 4：根因——满量程字段

帧本身完全合法：

```
2C 00 0E 07 D0 11
│  └─┬─┘ └─┬─┘ └─ 校验和 0x11
│    │     └────── 量程 0x07D0 = 2000 µg/m³
│    └──────────── 浓度 0x000E = 14 µg/m³
└───────────────── 帧头

校验：0x2C+0x00+0x0E+0x07+0xD0 = 0x111 → 低字节 0x11 ✓
```

但驱动里写着「B4B5 必须是 `03 E8`」，而规格书示例确实是 `03 E8`（1000 µg/m³）。**这颗模块自报 `07 D0`（2000 µg/m³）。**

于是每帧流程变成：校验通过 → 量程不符 → `bad_frames++` → `drop_(1)` 滑动重同步 → 缓冲区错位 → 下一帧继续不符……形成「异常帧 361 / 有效帧 0」的连锁。

**修正**：合法性只看 `帧头 0x2C + 校验和`，量程字段改为首次收到时打一条 INFO。

## 阶段 5：验证

```
[I][ze08c]: 累计 720 字节 / 有效帧 120 / 异常帧 0 / 残留 0｜GPIO5 电平=1
[I][ze08c]: 累计 900 字节 / 有效帧 150 / 异常帧 0 / 残留 0｜GPIO5 电平=1
```

30 秒 30 帧、150 帧全过、异常 0、缓冲区无残留。REST 接口返回 `{"value":5,"state":"5 µg/m³"}`。

最后做日志降噪（原先 1 帧/秒刷一行）：

| 指标 | 调整前 | 调整后 |
|---|---|---|
| 读数日志 | 每帧（~60 行/分） | 10 秒一行 |
| 累计统计 | 30 秒 | 60 秒 |
| 参照 | — | 与 CM1106 密度一致（75 秒窗口 8 行 vs 7 行） |

## 症状速查表

| 现象 | 判读 | 处理 |
|---|---|---|
| CH2O=NA，其他通道正常 | 只影响甲醛这一路，先看日志有无 `ze08` 标签 | 确认驱动是否参与编译（检查 `#ifdef`） |
| 日志无 `ze08` 输出 | 要么驱动没编译，要么宏把字符串剔了 | 取消 `ZE08_DEBUG` 注释，重新编译 |
| 30 秒 0 字节 + `电平=1` | 线路空闲，模块没在发 | 查模块 5 V 供电、极性、是否损坏 |
| 30 秒 0 字节 + `电平=0` | **线被外部拉低** | 查 TX 是否接到端口 1（GND）、分压下臂是否接反、是否短路 |
| 30 秒只收到 1 个字节 | 接触不良或线序错，非波特率问题 | 重新插拔、量通断 |
| 大量字节但有效帧 0、异常帧持续增长 | 协议字段判定过严（如量程硬校验） | 只保留帧头 + 校验和判定 |
| 字节数对得上但数值不变 | 模块在发固定值 | 检查是否处于标定/预热状态，正常应有小幅波动 |

## 三条可复用的经验

1. **引脚电平是最便宜的物理层证据**。加一行 `digitalRead`，就能区分「模块不说话」和「线被拉死」，比反复换线快得多。
2. **不要拿规格书里的"固定字段"做硬校验**。不同批次、不同量程版本的模块，量程/型号字段可能不一致。协议里真正可靠的只有帧头与校验和。
3. **规格书与实际型号要先对齐**。本项目在错误的协议（ZE08-CH2O）上花了整整一轮时间，而根因只是模块型号不同。
